# ビジネスルール

## BR-001: 担当割り当てルール（排他制御）

| 項目 | 内容 |
|------|------|
| ルール | 問い合わせの担当は「担当者未決定」状態のもののみ取得可能 |
| 条件 | `inquiry.status == 0 (WAITING) AND inquiry.assigned_operator_id IS NULL` |
| 違反時 | ConflictError（409）を返却 |
| 早い者勝ち | 同時に2人のオペレータが担当取得した場合、DBのトランザクションで先に更新したほうが取得成功 |

### 排他制御の実装方針
- SQLite のトランザクション＋ WHERE 条件による楽観的ロック
- `UPDATE inquiries SET assigned_operator_id = ?, status = 1 WHERE id = ? AND assigned_operator_id IS NULL AND status = 0`
- affected_rows == 0 の場合は ConflictError
- 対象は `status = 0 (WAITING)` のみ。`status = 3 (INPUTTING)` の問い合わせは担当取得できない

## BR-002: チャット送信権限ルール

| 項目 | 内容 |
|------|------|
| エンドユーザ | 自分が開始した問い合わせにのみメッセージ送信可能 |
| オペレータ | 自分が担当する問い合わせにのみメッセージ送信可能 |
| 終了済み | status == 2 (CLOSED) の問い合わせにはメッセージ送信不可 |

### 権限マトリクス
| 送信者 | 問い合わせ状態 | 担当者 | 送信可否 |
|--------|-------------|--------|---------|
| エンドユーザ | waiting (0) | - | ✓ |
| エンドユーザ | active (1) | 任意 | ✓ |
| エンドユーザ | closed (2) | - | ✗ |
| エンドユーザ | inputting (3) | - | ✓（送信不可にする処理は追加していない） |
| オペレータ | waiting (0) | - | ✗（まだ担当していない） |
| オペレータ | active (1) | 自分 | ✓ |
| オペレータ | active (1) | 他人 | ✗ |
| オペレータ | closed (2) | - | ✗ |
| オペレータ | inputting (3) | - | ✗（担当取得できないため担当者が存在しない） |

## BR-002-1: 入力中（INPUTTING）ステータスルール

| 項目 | 内容 |
|------|------|
| ステータスコード | 3（既存の 0・1・2 は変更しない） |
| 表示名 | 入力中 |
| 表示ステータス | `inputting`（assigned_operator_id に関係なく `others` にはならない） |
| 作成方法 | `InquiryRepository.create(initial_status=InquiryStatus.INPUTTING)` で明示指定 |
| 初期ステータスの許可値 | WAITING と INPUTTING のみ。ACTIVE・CLOSED・不明値は `ValueError` で拒否し INSERT しない |
| DBのデフォルト値 | `DEFAULT 0`（WAITING）を維持。引数を省略した既存の作成処理は WAITING のまま |
| 担当取得 | 不可（BR-001 の条件は WAITING のみ） |
| 終了処理 | 既存の終了処理は現在のステータスに関係なく CLOSED へ更新するため、INPUTTING の問い合わせも終了できる |

### 未実装（後続実装で対応する）
- INPUTTINGのタイムアウト自動終了処理
- 任意のステータスへ変更する汎用的な更新API・Repositoryメソッド

### 状態遷移
```
INPUTTING (3) --初回メッセージ送信--> WAITING (0) --担当取得--> ACTIVE (1) --終了--> CLOSED (2)
INPUTTING (3) --切断 / 明示終了--> CLOSED (2)
```

## BR-003: セッション終了ルール

| 条件 | 動作 |
|------|------|
| エンドユーザが「終了」ボタンを押す | 即座にセッション終了 |
| ブラウザのタブを閉じる | WebSocket切断検知でセッション終了 |
| 30分間操作がない | タイムアウトでセッション終了 |

### セッション終了時の共通処理
1. `inquiry.status` を `2 (CLOSED)` に更新
2. `inquiry.closed_at` に現在時刻を設定
3. システムメッセージ「ユーザーが退出しました」を Message テーブルに保存
4. 同じ問い合わせに接続中のオペレータにシステムメッセージをブロードキャスト
5. エンドユーザのWebSocket接続を切断
6. ConnectionManager からエンドユーザの接続を削除

### セッション終了後のオペレータ画面
- チャット画面にシステムメッセージ「ユーザーが退出しました」が表示される
- メッセージ入力欄・送信ボタンが無効化（disabled）される
- 会話履歴は引き続き閲覧可能

## BR-006: WebSocket接続ルール

### エンドユーザ接続
| 項目 | 内容 |
|------|------|
| 認証 | 不要 |
| 接続条件 | 制限なし（接続時にはDB書き込みなし、初回メッセージ送信時に問い合わせ作成） |
| 切断条件 | タブ閉じ / タイムアウト / 明示終了 |

### オペレータ接続
| 項目 | 内容 |
|------|------|
| 認証 | 必要（セッションCookieで検証） |
| 接続条件 | 対象問い合わせの担当者であること |
| 切断条件 | ログアウト / ブラウザ閉じ |
| 担当外の閲覧 | REST API経由で履歴閲覧は可（WebSocket接続は不可） |

## BR-008: オペレータ管理ルール

### オペレータ追加
| 項目 | 内容 |
|------|------|
| username | 必須、1文字以上、既存ユーザーと重複不可 |
| display_name | 必須、1文字以上 |
| パスワード | サーバー側で英数字12文字をランダム生成 |
| パスワード表示 | 追加成功時のレスポンスでのみ1回表示（再発行なし） |

### オペレータ削除
| 項目 | 内容 |
|------|------|
| 自分自身 | 削除不可（ForbiddenError 403） |
| 他のオペレータ | 制約なし（担当中の問い合わせがあっても削除可） |
| 関連データ | オペレータ削除時、関連する sessions レコードも削除する |

### パスワード自動生成仕様
| 項目 | 値 |
|------|------|
| 文字種 | 英大文字 + 英小文字 + 数字 |
| 長さ | 12文字 |
| 生成方法 | Python `secrets` モジュールで暗号学的に安全な乱数生成 |

## BR-009: 時刻管理ルール

| 項目 | 内容 |
|------|------|
| タイムゾーン | JST（日本標準時、UTC+9） |
| 保存形式 | ISO 8601 形式の JST 文字列（例: `2025-01-15T14:30:00+09:00`） |
| ヘルパー関数 | `now_jst()` — `database.py` に定義 |
| DB DEFAULT | 使用しない。全時刻はアプリケーション側で `now_jst()` を使用して明示的に INSERT する |
| 表示 | フロントエンドでもJSTとして表示 |
